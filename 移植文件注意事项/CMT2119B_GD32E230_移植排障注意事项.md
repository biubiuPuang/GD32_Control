# CMT2119B / PH2119BBA 移植到 GD32E230 排障注意事项

> 适用场景：GD32E230C8T6 通过 GPIO 软件模拟 SPI 控制 CMT2119B / PH2119BBA 模块，只使用无线发送功能，发送模式优先采用 FIFO Packet 模式。

---

## 1. 当前硬件接线记录

| PH2119BBA 模块引脚 | 功能 | GD32E230 引脚 | 方向 | 说明 |
|---|---|---|---|---|
| FCSB | FIFO 片选，低有效 | PB0 | 输出 | 访问 FIFO 时拉低 |
| CSB | 寄存器片选，低有效 | PA4 | 输出 | 访问寄存器时拉低 |
| SDIO | SPI 双向数据 | PA7 | 输入/输出切换 | 软件 SPI 使用，不能简单当普通 MOSI 一直输出 |
| SCLK | SPI 时钟 | PA5 | 输出 | 软件 SPI 时钟 |
| GPIO3 | INT2 / TX_DONE | PB1 | 输入 | 用于判断发送完成，第一版建议轮询 |
| VCC | 电源 | 3V3 | 电源 | 不要接 5V |
| GND | 地 | GND | 地 | 必须与 MCU 共地 |
| ANT | 天线 | 433MHz 天线 | RF | 不接 MCU |

建议第一版不要使用硬件 SPI，先全部使用普通 GPIO 软件模拟 SPI。

---

## 2. 移植原则

### 2.1 不要直接把 STM32 Demo 整体搬到 GD32E230

原 Demo 是：

```text
STM32F103VC + CMT2300A
```

当前目标是：

```text
GD32E230C8T6 + CMT2119B / PH2119BBA
```

因此这些内容不要直接移植：

```text
STM32F10x 标准外设库
system_stm32f10x.c
stm32f10x_it.c
LCD12864
蜂鸣器
按键
LED Demo 逻辑
CMT2300A 接收逻辑
```

### 2.2 可参考但不能完全照抄的内容

可以参考 CMT2300A Demo 的：

```text
cmt_spi3.c / cmt_spi3.h      软件 SPI 时序
radio.c                     RF_Init 结构
main.c                      Radio_Send_FixedLen 发送流程
cmt2300a.c                  寄存器/FIFO/状态切换组织方式
```

但要注意：

```text
CMT2300A != CMT2119B
```

寄存器地址、状态命令、中断配置、RFPDK 参数都必须以 CMT2119B 数据手册、AN167 或 RFPDK 导出结果为准。

---

## 3. 推荐代码分层

建议保持如下结构：

```text
Hardware/cmt2119b/
├── cmt2119b_port.c      GD32E230 GPIO、延时、SDIO 输入/输出切换
├── cmt2119b_port.h
├── cmt2119b_spi.c       软件 SPI，寄存器读写、FIFO 写入
├── cmt2119b_spi.h
├── cmt2119b.c           CMT2119B 初始化、状态切换、发包流程
├── cmt2119b.h
├── cmt2119b_params.h    RFPDK 导出的 CMT2119B 参数
├── radio_tx.c           应用层发送接口
└── radio_tx.h
```

应用层只调用：

```c
radio_tx_init();
radio_tx_send(buf, len);
```

不要让 `main.c` 直接操作 CMT2119B 寄存器。

## 4. CSB / FCSB 注意事项

CMT2119B 模块有两个片选：

| 片选 | 用途 | 正确状态 |
|---|---|---|
| CSB | 访问寄存器 | 访问寄存器时拉低 |
| FCSB | 访问 FIFO | 写 FIFO 时拉低 |

关键规则：

```text
CSB 和 FCSB 不能同时为低。
```

访问寄存器时：

```text
CSB  = 0
FCSB = 1
```

访问 FIFO 时：

```text
CSB  = 1
FCSB = 0
```

如果逻辑分析仪看到 `CSB` 和 `FCSB` 同时拉低，必须先修这个问题。

---

## 5. SDIO 双向数据脚注意事项

`SDIO` 是双向脚，不是单纯 MOSI。

### 5.1 写寄存器 / 写 FIFO

写数据时：

```text
SDIO 配置为 GPIO 输出
MCU 驱动 SDIO 输出 0/1
```

### 5.2 读寄存器

读寄存器时：

```text
先发送读命令地址
然后在接收数据前把 SDIO 切换为输入
再读取芯片输出的数据
```

常见错误：

```text
读寄存器时 SDIO 仍然保持输出，导致 MCU 和 CMT2119B 同时驱动 SDIO。
```

这种情况可能造成：

```text
读回值一直是 0x00
读回值一直是 0xFF
波形异常
芯片发热或 IO 电平冲突
```

---

## 6. 软件 SPI 时序注意事项

CMT2119B SPI 访问时，数据通常按 MSB first 传输。

基础时序原则：

```text
SCLK 低电平时准备 SDIO 数据
SCLK 上升沿附近采样数据
```

如果通信不稳定，优先把软件 SPI 延时加大，不要一开始追求速度。

建议排查顺序：

1. 先把 SCLK 频率降到很低，例如几十 kHz 到几百 kHz。
2. 用逻辑分析仪确认 SCLK、SDIO、CSB、FCSB 波形。
3. 确认地址字节和数据字节都是 MSB first。
4. 确认读寄存器前 SDIO 已切换为输入。
5. 确认每次 FIFO 字节写入之间有足够间隔。

## 7. 初始化阶段排障

推荐初始化顺序：

```text
1. systick_config()
2. cmt2119b_port_init()
3. cmt2119b_spi_init()
4. cmt2119b_init()
5. 加载 RFPDK 参数
6. 配置 GPIO3 为 TX_DONE / INT2
7. 进入 sleep 或 standby
```

如果初始化后无任何波形，检查：

```text
1. Keil 工程是否添加了 cmt2119b_port.c / cmt2119b_spi.c / cmt2119b.c / radio_tx.c
2. Include Path 是否添加了 Hardware/cmt2119b
3. main.c 是否实际调用了 radio_tx_init() / radio_tx_send()
4. PA4、PA5、PA7、PB0、PB1 的 GPIO 时钟是否开启
5. 引脚是否被其他外设复用占用
```

---

## 8. RFPDK 参数注意事项

不要直接使用 CMT2300A Demo 里的：

```text
cmt2300a_params.h
```

必须用 RFPDK 选择：

```text
Part Number: CMT2119B
```

然后按实际需求导出 CMT2119B 参数。

如果暂时没有接收端参数，可先用测试配置：

```text
Frequency: 433.920 MHz
Modulation: GFSK
Data Rate: 9.6 kbps
Deviation: 20 kHz
Packet: Fixed Length
Payload Length: 32 bytes
Whitening: Disable
Tx Power: +13 dBm 优先，确认供电后再考虑 +20 dBm
```

注意：

```text
代码编译无报错 ≠ 无线参数正确 ≠ 接收端一定能收到。
```

如果接收端参数不一致，即使 CMT2119B 正常发射，也可能完全收不到。

---

## 9. TX_DONE / GPIO3 注意事项

当前接线：

```text
GPIO3 -> PB1
```

第一版建议轮询 PB1，不要先用外部中断。

发送流程：

```text
1. GoStby
2. ClearInterruptFlags
3. ClearTxFifo
4. WriteFifo
5. GoTx
6. 等待 GPIO3 / TX_DONE
7. ClearInterruptFlags
8. GoSleep
```

如果 PB1 一直没有 TX_DONE：

```text
1. 确认 GPIO3 是否在 RFPDK 或寄存器中配置为 INT2 / TX_DONE
2. 确认 TX_DONE 中断是否使能
3. 确认 PB1 配置为输入
4. 尝试 GPIO_PUPD_NONE / GPIO_PUPD_PULLUP / GPIO_PUPD_PULLDOWN
5. 用示波器直接看模块 GPIO3 脚是否有跳变
6. 确认芯片是否真的进入 TX 状态
7. 确认 FIFO 里有数据
8. 确认 Payload Length 和写入 FIFO 长度一致
```

## 10. FIFO 发送注意事项

CMT2119B 支持 64-byte TX FIFO。

建议第一版限制：

```text
len <= 64
```

如果使用固定包长，例如 32 字节，则：

```text
RFPDK Payload Length = 32
radio_tx_send(buf, 32)
```

二者必须一致。

常见错误：

| 现象 | 可能原因 |
|---|---|
| TX_DONE 不来 | FIFO 没写进去、未进入 TX、GPIO3 未配置为 TX_DONE |
| 接收端长度不对 | RFPDK 包长和实际写 FIFO 长度不一致 |
| 只能发一次 | 中断标志未清、FIFO 未清、状态未回到 standby/sleep |
| 偶发失败 | FIFO 字节间隔太短、SCLK 太快、供电压降 |

---

## 11. 供电注意事项

CMT2119B 发射功率较高时电流明显增大。

尤其 +20 dBm 时，发射电流可能达到几十 mA 甚至更高。

注意：

```text
1. VCC 只能接 3.3V，不要接 5V。
2. MCU 板载 3.3V LDO 电流要足够。
3. 模块 VCC 和 GND 旁边建议有去耦电容。
4. 发射瞬间如果电压跌落，可能导致 SPI 异常、TX_DONE 不来或芯片复位。
5. 初次调试建议先用 +13 dBm，不要直接 +20 dBm。
```

建议用万用表或示波器检查：

```text
VCC 静态电压
发射瞬间 VCC 是否明显下跌
GND 是否可靠共地
```

---

## 12. 天线注意事项

`ANT` 不接 MCU。

必须接合适的 433MHz 天线，或者至少接与模块设计匹配的天线焊盘/弹簧天线。

注意：

```text
1. 不接天线时，近距离可能偶尔能收到，但距离和稳定性会很差。
2. +20 dBm 空载发射不推荐长期运行。
3. 天线附近不要紧贴大面积金属。
4. 模块地和主板地要可靠连接。
```

## 13. 分阶段验证方法

### 阶段 1：编译验证

目标：Keil 无报错、无未定义符号。

重点检查：

```text
.c 文件是否加入工程
.h 路径是否加入 Include Path
函数名是否一致
```

---

### 阶段 2：GPIO 波形验证

目标：能看到 PA4、PB0、PA5、PA7 波形。

检查点：

```text
PA4 / CSB 初始化为高
PB0 / FCSB 初始化为高
PA5 / SCLK 初始化为低
PA7 / SDIO 写时有数据
```

---

### 阶段 3：SPI 读写验证

目标：能读写 CMT2119B 寄存器。

如果读回一直异常，检查：

```text
SDIO 输入/输出方向
CSB/FCSB 是否正确
SCLK 是否太快
地址读写位是否正确
模块是否供电
模块是否焊接/接线良好
```

---

### 阶段 4：RFPDK 参数加载验证

目标：能把 CMT2119B 参数表写入寄存器。

注意：

```text
参数必须来自 CMT2119B，不是 CMT2300A。
```

---

### 阶段 5：FIFO 写入验证

目标：写 FIFO 时 FCSB 拉低，SCLK 和 SDIO 有 32 字节或指定长度的数据波形。

检查：

```text
CSB 是否保持高
FCSB 是否按 FIFO 写入时序拉低
每个字节之间是否有足够延时
```

---

### 阶段 6：TX_DONE 验证

目标：GoTx 后 PB1 能读到 TX_DONE。

如果没有：

```text
优先检查 GPIO3 功能配置和中断使能。
```

---

### 阶段 7：无线接收验证

目标：接收端能收到数据。

如果收不到，检查参数是否一致：

```text
频率
调制方式
数据率
频偏
前导码
同步字
包长
CRC
Whitening
编码方式
发射功率
```

## 14. 常见故障速查表

| 故障现象 | 优先怀疑点 | 排查动作 |
|---|---|---|
| 编译报 `xxx.h` 找不到 | Include Path 未添加 | Keil 添加 `..\Hardware\cmt2119b` |
| 编译报函数未定义 | `.c` 文件未加入工程 | 把 `cmt2119b_port.c`、`cmt2119b_spi.c`、`cmt2119b.c`、`radio_tx.c` 加入工程 |
| 没有任何 SPI 波形 | main 未调用发送、GPIO 时钟未开 | 检查 `radio_tx_init()` / `radio_tx_send()` 是否执行 |
| CSB/FCSB 同时为低 | 片选控制错误 | 修改 SPI 底层，保证二者互斥 |
| 读寄存器全是 0xFF | SDIO 悬空、芯片未响应、CSB 错 | 检查 SDIO 输入、CSB、供电、SCLK |
| 读寄存器全是 0x00 | SDIO 被拉低、方向错误 | 检查 SDIO 是否仍配置为输出低 |
| 写 FIFO 后不发送 | 未 GoTx、FIFO 未清、参数错误 | 检查发送流程和寄存器配置 |
| TX_DONE 一直不来 | GPIO3 未配置 TX_DONE | 检查 RFPDK GPIO/INT 配置 |
| 只能发一次 | 中断标志/FIFO/状态未清 | 每次发送前清中断、清 FIFO、GoStby |
| 近距离也收不到 | RF 参数不一致 | 对齐频率、调制、速率、同步字、CRC、包长 |
| 发送时 MCU 复位 | 电源压降 | 降低发射功率、增强 3.3V 供电、加电容 |
| 发射距离很短 | 天线/匹配/功率问题 | 检查 ANT、天线、供电、RFPDK 功率 |

## 15. 调试建议顺序

不要一上来就判断“无线没发出去”。建议固定按下面顺序排查：

```text
1. 工程是否编译通过
2. main 是否调用 radio_tx_send
3. GPIO 是否初始化正确
4. CSB/FCSB/SCLK/SDIO 是否有正确波形
5. 是否能读写寄存器
6. RFPDK 参数是否为 CMT2119B
7. FIFO 是否写入正确长度
8. 是否进入 TX 状态
9. GPIO3 是否输出 TX_DONE
10. 接收端参数是否完全一致
11. 供电和天线是否可靠
```

每次只改一个变量，避免同时改代码、参数、接线，导致无法判断问题来源。

## 16. 和原 CMT2300A Demo 的对应关系

原 Demo 发送函数大致流程：

```c
CMT2300A_GoStby();
CMT2300A_ClearInterruptFlags();
CMT2300A_ClearTxFifo();
CMT2300A_EnableWriteFifo();
CMT2300A_WriteFifo(pBuf, len);
CMT2300A_GoTx();

while (1) {
    if (CMT2300A_ReadGpio3()) {
        CMT2300A_ClearInterruptFlags();
        CMT2300A_GoSleep();
        return 1;
    }
}
```

移植后 CMT2119B 发送流程应保持类似：

```c
cmt2119b_go_stby();
cmt2119b_clear_interrupt_flags();
cmt2119b_clear_tx_fifo();
cmt2119b_write_fifo(buf, len);
cmt2119b_go_tx();

while (timeout--) {
    if (cmt2119b_gpio3_read()) {
        cmt2119b_clear_interrupt_flags();
        cmt2119b_go_sleep();
        return CMT2119B_OK;
    }
}
```

差异点：

```text
函数结构可以参考。
寄存器地址、参数表、GPIO 配置不能直接照抄。
```

## 17. 后续优化方向

第一版建议保持简单：

```text
GPIO 软件 SPI
PB1 轮询 TX_DONE
固定包长
单包发送
```

确认稳定后再考虑：

```text
1. PB1 改为 EXTI 外部中断
2. 软件 SPI 改为硬件半双工 SPI
3. 增加发送状态机
4. 增加发送失败重试
5. 增加低功耗 sleep / wakeup
6. 支持不同包长
7. 支持配置多个 RFPDK 参数集
```

不要在第一版同时做这些优化。

---

## 18. 最重要的三条

1. **CMT2119B 参数必须由 RFPDK 选择 CMT2119B 后导出，不能直接用 CMT2300A 参数。**
2. **SDIO 是双向脚，读寄存器前必须切换为输入。**
3. **CSB 和 FCSB 不能同时拉低，寄存器访问和 FIFO 访问必须分开。**
