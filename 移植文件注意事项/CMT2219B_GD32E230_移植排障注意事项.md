# CMT2219B 接收端移植与排查总结

## 1. 当前目标

本工程目标是在原有 GD32E230 工程中，同时支持：

- PH2119BBA / CMT2119B 发送模块
- PH2219BBA / CMT2219B 接收模块

当前接收端驱动已经按官方 CMT2300A 接收 Demo 的参数和流程移植到本工程中。

接收端首版目标：

- 频率：433.920 MHz
- 调制：GFSK
- 数据速率：9.6 kbps
- 包格式：固定长度包
- 包长：32 字节
- 白化：关闭
- CRC：关闭

## 2. 当前硬件连接

### 2.1 接收端 PH2219BBA / CMT2219B

| PH2219BBA 引脚 | 名称 | GD32E230 引脚 | 说明 |
| --- | --- | --- | --- |
| 1 | FCSB | PB12 | FIFO 片选，普通 GPIO 输出 |
| 2 | CSB | PB13 | 寄存器 SPI 片选，普通 GPIO 输出，低有效 |
| 3 | SDIO | PB15 | 3 线 SPI 数据脚，读写时需要切换输入/输出 |
| 4 | CLK | PB14 | 3 线 SPI 时钟 |
| 5 | GPIO3 | PB10 | 接收中断输入，当前按 PKT_DONE 判断收包 |
| 7 | VCC | 3V3 | 只能接 3.3V |
| 8 | GND | GND | 共地 |
| 9 | ANT | 433MHz 接收天线 | 不接 MCU |
| 10 | GND | GND | 共地，建议也接 |

### 2.2 发送端 PH2119BBA / CMT2119B

发送端保持原来的连接，不要改。

| PH2119BBA 引脚 | GD32E230 引脚 |
| --- | --- |
| FCSB | PB0 |
| CSB | PA4 |
| SDIO | PA7 |
| SCLK | PA5 |
| GPIO3 | PB1 |
| VCC | 3V3 |
| GND | GND |
| ANT | 433MHz 发射天线 |

## 4. 各文件作用

### 4.1 cmt2219b_port.h / cmt2219b_port.c

作用：只负责 GD32E230 的 GPIO。

主要内容：

- 初始化 PB12 / PB13 / PB14 / PB15 / PB10
- 控制 FCSB、CSB、CLK、SDIO 输出高低电平
- 读取 SDIO 输入
- 读取 GPIO3 输入
- 切换 SDIO 输入/输出模式
- 调用 `delay_us()` / `delay_ms()` 做延时

重点排查：

```text
PB12 -> FCSB
PB13 -> CSB
PB14 -> CLK
PB15 -> SDIO
PB10 -> GPIO3
```

如果引脚没波形，优先查这个文件。

### 4.2 cmt2219b_spi.h / cmt2219b_spi.c

作用：模拟 CMT2219B 的 3 线 SPI。

主要接口：

```c
void cmt2219b_spi_init(void);
void cmt2219b_spi_write_reg(uint8_t addr, uint8_t dat);
uint8_t cmt2219b_spi_read_reg(uint8_t addr);
void cmt2219b_spi_write_fifo(const uint8_t *buf, uint16_t len);
void cmt2219b_spi_read_fifo(uint8_t *buf, uint16_t len);
```

寄存器访问时：

```text
FCSB = 高
CSB  = 低
CLK  = 输出时钟
SDIO = 写寄存器时输出，读寄存器时先输出地址再切输入
```

FIFO 访问时：

```text
CSB  = 高
FCSB = 按字节拉低
CLK  = 输出时钟
SDIO = 读 FIFO 时输入，写 FIFO 时输出
```

如果芯片检测失败，重点查这个文件的 SPI 时序。

### 4.3 cmt2219b_params.h

作用：保存无线参数表。

当前参数来自官方 CMT2300A 接收 Demo，先用于 CMT2219B 首版接收验证。

当前参数目标：

```text
433.920 MHz
GFSK
9.6 kbps
固定 32 字节包
白化关闭
CRC 关闭
```

如果 SPI 正常、芯片也能识别，但一直收不到包，后续重点怀疑这个参数文件和发送端参数不匹配。

### 4.4 cmt2219b.h / cmt2219b.c

作用：芯片控制层。

主要接口：

```c
uint8_t cmt2219b_init(void);
uint8_t cmt2219b_is_exist(void);
uint8_t cmt2219b_go_sleep(void);
uint8_t cmt2219b_go_stby(void);
uint8_t cmt2219b_go_rx(void);
void cmt2219b_enable_read_fifo(void);
void cmt2219b_clear_rx_fifo(void);
void cmt2219b_clear_interrupt_flags(void);
uint8_t cmt2219b_packet_received(void);
```

主要初始化流程：

```text
1. 初始化 GPIO 和 3 线 SPI
2. 软件复位
3. 进入 STBY
4. 配置 CFG_RETAIN / RSTN_IN / LOCKING_EN
5. 关闭 LFOSC
6. 清中断
7. 写入参数表
8. 配置 GPIO3 输出 INT2
9. 配置 INT2 为 PKT_DONE
10. 使能 PKT_DONE / PREAM_OK / SYNC_OK
11. 进入 SLEEP
```

### 4.5 radio_rx.h / radio_rx.c

作用：应用层接收封装。

上层只需要调用：

```c
radio_rx_init();
radio_rx_poll_packet(rx_buf, 32);
```

`radio_rx_init()` 做：

```text
1. 初始化 CMT2219B
2. 检测芯片是否存在
3. 进入 STBY
4. 使能读 FIFO
5. 清中断
6. 清 RX FIFO
7. 进入 RX
```

`radio_rx_poll_packet()` 做：

```text
1. 读 GPIO3
2. GPIO3 没触发，返回 0
3. GPIO3 触发后：
   - 进入 STBY
   - 读取 FIFO
   - 清 RX FIFO
   - 清中断
   - 重新进入 RX
   - 返回 1
```

## 5. 当前 main.c 测试逻辑

当前 `User/main.c` 逻辑是：

```text
1. 初始化 SysTick
2. 初始化 tx_buf，内容为 1 到 32
3. 初始化发送端 radio_tx_init()
4. 初始化接收端 radio_rx_init()
5. while 循环中：
   - 如果接收端初始化成功，就轮询接收
   - 收到数据后 rx_count++
   - 每 1 秒发送一次 tx_buf
```

当前关键调试变量：

```c
static uint8_t tx_buf[32];
static uint8_t rx_buf[32];
static volatile uint32_t rx_count;
static volatile uint8_t radio_rx_ready;
```

调试时重点观察：

```text
radio_rx_ready
rx_count
rx_buf[0..31]
```

正常预期：

```text
radio_rx_ready = 1
收到包后 rx_count 递增
rx_buf 中能看到收到的数据
```

## 7. 推荐排查顺序

不要一上来就查无线收不到包。按下面顺序排查。

### 第一步：先看编译

目标：

```text
0 Error(s)
```

常见问题：

| 现象 | 优先检查 |
| --- | --- |
| 找不到 `radio_rx.h` | Include Path 是否加了 `..\Hardware\cmt2219b` |
| 找不到 `uint8_t` | 对应 `.h/.c` 是否包含 `<stdint.h>` |
| 找不到 `delay_us` / `delay_ms` | `cmt2219b_port.c` 是否包含 `systick.h` |
| 找不到 `cmt2219b_xxx` 函数 | `.c` 文件是否加入 Keil 工程 |

### 第二步：看静态电平

程序运行到初始化之后，空闲时大致应该是：

```text
PB13 / CSB  = 高
PB12 / FCSB = 高
PB14 / CLK  = 低
PB15 / SDIO = 高或输入上拉
```

如果这些电平不对，优先查：

```text
cmt2219b_port_init()
```

### 第三步：看 SPI 波形

在这些函数处打断点：

```c
cmt2219b_spi_write_reg()
cmt2219b_spi_read_reg()
```

单步运行，看：

```text
PB13 / CSB 有没有拉低
PB14 / CLK 有没有时钟
PB15 / SDIO 写寄存器时有没有数据
读寄存器时 PB15 是否切换成输入
PB12 / FCSB 寄存器访问时是否保持高
```

如果没有 SPI 波形，先别查无线参数。

### 第四步：看芯片检测

重点函数：

```c
cmt2219b_is_exist()
```

它的逻辑是：

```text
1. 读 0x48 原值
2. 写 0xAA 到 0x48
3. 再读 0x48
4. 如果读回 0xAA，说明 SPI 基本正常
5. 恢复原值
```

如果 `radio_rx_ready = 0`，很可能是这里失败。

优先检查：

```text
1. CMT2219B 是否 3.3V 供电
2. GND 是否共地
3. PB13 是否真的接 CSB
4. PB14 是否真的接 CLK
5. PB15 是否真的接 SDIO
6. PB12 是否真的接 FCSB
7. SDIO 读寄存器时是否已经切成输入
```

### 第五步：看是否进入 RX

重点函数：

```c
cmt2219b_go_rx()
```

如果 `cmt2219b_is_exist()` 成功，但 `radio_rx_ready` 仍然是 0，就查：

```text
1. cmt2219b_go_stby() 是否成功
2. cmt2219b_go_rx() 是否成功
3. cmt2219b_get_chip_status() 返回值是否符合预期
```

当前模式状态值：

```text
SLEEP = 0x01
STBY  = 0x02
RX    = 0x05
```

### 第六步：看 GPIO3 是否触发

当前代码用：

```c
cmt2219b_packet_received()
```

实际就是读取：

```text
PB10 / GPIO3
```

当前配置思路：

```text
GPIO3 输出 INT2
INT2 配置为 PKT_DONE
```

如果 `radio_rx_ready = 1`，但 `rx_count` 一直不增加，重点查：

```text
1. PB10 是否接到 CMT2219B GPIO3
2. PB10 是否有电平变化
3. GPIO3 是否真的是高电平有效
4. INT2 是否配置成 PKT_DONE
5. 发射端和接收端参数是否一致
```

### 第七步：看 FIFO 读取

如果 PB10 有变化，但是 `rx_buf` 数据不对，重点查 FIFO。

FIFO 读时应该是：

```text
CSB  = 高
FCSB = 按字节拉低
CLK  = 每字节 8 个时钟
SDIO = 输入
```

重点函数：

```c
cmt2219b_spi_read_fifo()
cmt2219b_enable_read_fifo()
cmt2219b_read_fifo()
```

常见问题：

```text
1. 没有调用 cmt2219b_enable_read_fifo()
2. 读 FIFO 时 SDIO 没切成输入
3. FCSB 没有按字节拉低
4. 读完后没有清 RX FIFO
5. 读完后没有重新进入 RX
```

## 8. 常见现象和判断

### 8.1 radio_rx_ready = 0

说明接收端初始化失败。

优先查：

```text
1. cmt2219b_is_exist() 是否失败
2. SPI 读写是否正常
3. SDIO 输入/输出切换是否正常
4. CMT2219B 供电是否为 3.3V
5. CSB / FCSB 是否接反
```

### 8.2 radio_rx_ready = 1，但 rx_count 不增加

说明初始化基本通过，但没有判断到收包。

优先查：

```text
1. PB10 / GPIO3 有没有电平变化
2. GPIO3 中断输出配置是否正确
3. 发射端是否真的在发包
4. 收发频率、速率、包长是否一致
5. 天线是否连接
6. 发射和接收天线是否太近导致过载
```

### 8.3 rx_count 增加，但 rx_buf 数据不对

说明 GPIO3 已触发，但 FIFO 读取可能有问题。

优先查：

```text
1. cmt2219b_enable_read_fifo() 是否调用
2. cmt2219b_spi_read_fifo() 时 FCSB 是否动作
3. PB15 / SDIO 读 FIFO 时是否为输入
4. 是否读了 32 字节
5. 发射端数据是否确实是 1 到 32
```

### 8.4 SPI 有写波形，但读回始终不对

优先查：

```text
1. SDIO 是否在读之前切换为输入
2. PB15 是否被外部硬拉高或硬拉低
3. CSB 是否低有效
4. FCSB 是否误拉低影响寄存器访问
5. CLK 采样边沿是否和芯片要求一致
```

## 9. 当前首版代码的注意事项

1. 当前参数来自 CMT2300A 官方 Demo，不是 CMT2219B 专用 RFPDK 参数。
2. 如果 SPI 正常但始终收不到，后续需要优先确认 CMT2219B 是否完全兼容这组寄存器参数。
3. 当前用 GPIO3 / PB10 轮询判断收包，没有使用 EXTI 中断。
4. 当前主循环每 1 秒发送一次，同时轮询接收。若同一块板自发自收，可能需要注意收发模块天线距离和射频前端过载。
5. 当前 `rx_count` 只是调试用计数，不代表数据内容一定正确。
6. 当前 `radio_rx_poll_packet()` 收到 GPIO3 触发后固定读 `len` 字节，调用时建议传 32。

## 11. 一句话排查原则

```text
先确认 GPIO，再确认 SPI，再确认芯片读写，再确认 RX 状态，最后才查无线收包。
```

不要一开始就从无线参数查起。只要 `cmt2219b_is_exist()` 还没通过，问题基本就在供电、接线、GPIO 或 SPI 时序。
