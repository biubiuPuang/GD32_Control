### 2.3 已识别冲突与注意事项

1. **PA8/PA9 功能标注冲突** ❓：MCU 侧图注写"PA8=上升继电器、PA9=下降继电器"（P2 U7 右侧注释），而继电器侧图注写"U12/KA1 通道=下降、U13/KA2 通道=上升"（P2 左下注释，U12 输入侧网络确为 PA8）。两处相反，**编码前必须与硬件确认**，确认前在代码中用 `MOTOR_UP_PIN`/`MOTOR_DN_PIN` 宏隔离，便于一键交换。
2. **PB3/PB4 功能两解** ❓：MCU 侧图注为"上升键/下降键"，但 P1 端子标注为 UL2/DL2（上/下限位回路 LIFT1/LOWER1）。需硬件确认这两个输入到底代表按键还是限位返回。
3. **SPI_SDIO 是单根双向数据线**（CMT2219B 为 3 线 SPI）：不能直接用标准全双工 SPI 收发电路，建议 GPIO 模拟时序，或用 SPI 半双工/单线模式（GD32E230 SPI 支持性 📖 待查参考手册）。
4. **PA6（脚16）未见网络** 🔎：紧邻 SPI 组但原理图未连，按未用引脚处理（配置为输入下拉或模拟输入降功耗），待硬件确认无焊接跳线。
5. 未用 GPIO：PA0、PA1、PA6、PA11、PA12、PA15、PB1、PB2、PB7、PB8、PB11、PB14、PB15、PF6、PF7（✅ P2 无网络）。其中 **PB8/PB9 附近有 LED2+R12(1k)**，但 LED 另一端接 VCC 还是 MCU 脚、高有效还是低有效，图上分辨不清 ❓，点亮前先与硬件核对。
6. 板级指示灯 LED1（P1，K_PERMIT 链路）由硬件安全链驱动，**MCU 不可控**。

| U15 | SN74LVC1G32（或门） | ESTOP_SENSE + MCUESTOP → NK_PERMIT（图注"或门，有一路输入高电平则急停"） | ✅ |
| U19 | 74LVC1G14（反相） | NK_PERMIT → K_PERMIT | **K_PERMIT 高=允许**（图注"高电平控制输出安全电源"）✅ |

### 3.7 电源与安全执行（P1）

- 变压器 AMP4116T0509D：380V→9V/44mA + 23V/0.2A ✅
- 23V → D2(DB107S) 整流 → **24V** rail（继电器、光耦输入回路、控制回路）✅
- 9V → D4(DB107S) 整流 → LDO1 CJ7805 → **+5V** → U1 AMS1117-3.3 → **VCC 3.3V** ✅
- **K_PERMIT 高电平** → Q8(MMBT3904) → RLY3(HFD23/024-1HS) 吸合 → 输出安全电源 **CTRL_SAFE** 到 CN1-8；同时驱动 Q9(YFW13005AD) → 主接触器 **KM1**(B7-30-10-P) 线圈 ✅（图注"按下急停或者软件急停切断"）
- 即：**急停（硬件）或 PB10=高（软件）→ K_PERMIT 变低 → CTRL_SAFE 断电 + KM1 断开三相主电源**。此链路由纯硬件完成，MCU 无法旁路 ✅
- R2 14D471K 压敏、F1/F2 保险、LED1 运行指示（硬件驱动，MCU 不可控）✅

### 3.8 本板不涉及的外设

原理图中**没有**：ADC 采样通道、I²C 器件、PWM 输出、CAN、USB、外部 Flash/存储。触摸与温湿度传感在此板原理图上不存在（若产品需要，属新需求）。定时器仅按软件需要自用（系统节拍、消抖、超时），无硬件约束。

## 五、运行逻辑与控制约束

### 5.1 输入解释（低有效，注意反相）

| 物理意义 | MCU 读法 | 结论 |
| --- | --- | --- |
| 有线 UP/DOWN/FAST 键按下（24V 送达） | 对应光耦输出拉低 | PB5=低 → 快速键有效；UP/DN 键经 UPSIG/DNSIG 进硬件逻辑，**MCU 没有独立的 UP/DN 数字输入脚**，只能读 PB3/PB4（LIFT1/LOWER1 回路）❓——若软件需要直接知道有线升降按键状态，需硬件确认 PB3/PB4 语义（见 2.3 冲突 2） |
| 限位/回路返回 LIFT1/LOWER1 | PB3/PB4=低 | 🔎 表示对应方向回路导通（按键+限位均通）；断开了对应回路=高 |
| T1_RAW | PB6=低 | 🔎 热保护/故障类信号，含义❓ |
| 急停 | MCU 读不到 | 硬件直接切断 CTRL_SAFE 与 KM1 ✅；表现为全部 24V 输入失效（PB3~PB6 全变高），软件可据此🔎推断急停/安全电源断开 |

### 5.2 输出控制

| 目标 | 操作 | 约束 |
| --- | --- | --- |
| 上升 | PA_up=高（PA8 或 PA9，待 2.3 确认） | 软件互锁：先确认另一路为低，延时（换相间隔，时长待需求❓）再吸合 |
| 下降 | PA_dn=高 | 同上 |
| 快速 | PA10=高 | 与升/降的组合规则待需求❓ |
| 无线命令 | PB12/PB13=高 | 硬件已做"有线优先"与"上下互锁"，软件仍应避免同时输出 ✅ |
| 软件急停 | PB10=高 | 立即切断安全电源与主接触器（硬件执行）；恢复条件待需求❓（是否自动恢复、是否需人工复位） |

### 5.3 硬件联锁清单（软件不可违背，也无需重复实现）

1. 急停按钮或 MCUESTOP → K_PERMIT=低 → CTRL_SAFE + KM1 断电（纯硬件，最高优先级）✅
2. DRV_UP 与 DRV_DN 硬件互斥（U25）✅
3. 任何有线动作 → WIRED_IDLE=0 → 无线命令被封锁（U20，有线优先）✅
4. 外部限位开关串在 24V 命令回路中（UP_PRE_LIMIT/DN_PRE_LIMIT 经 CN1 进出），限位动作=回路物理断开 ✅

### 5.4 软件必须自做的约束

- KA1/KA2（升/降换相继电器）**软件互锁 + 换向死区时间**（硬件对这两路没有互锁！触点切换 380V 相序，同时吸合=相间短路风险🔎）——这是本设计软件侧最关键的安全约束。
- 输入消抖（光耦 + 机械触点，时长按实测，勿凭空定值）。
- 继电器动作最大频率/最小间隔（触点寿命与电弧，参数待需求/器件手册）。
- 无线命令超时：收不到遥控心跳后的处理策略 ❓待需求（建议超时即撤 PB12/PB13，🔎建议非结论）。
- 状态机建议（🔎建议）：`IDLE(全释放) → UP_RUN / DN_RUN（可叠加 FAST） → 任意限位/故障/急停推断 → SAFE_STOP（全释放+视需求决定是否拉 PB10）`。哪些来自需求哪些只是建议已在文中标注。
